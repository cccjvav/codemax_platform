# 微信日账读取与差异报告

## 这是什么，不是什么

大白话：把微信的“一天交易清单”和本站“原始收款凭证”并排检查，找出需要人核查的地方。像核对仓库进货单，发现少了一张单据不等于可以直接改库存。

本批提供**默认关闭、显式运行的运维 CLI**，不是网页批量处理按钮。申请普通直连商户现代格式的 `ALL` 日账；只对配置中的商户＋AppID＋Native＋CNY付款做双向比对。退款行只列为发起快照，不与完成日期作反向匹配，不证明到账或退款完成。

- 不收上传文件，不接任意下载 URL，不提供公开下载报告接口。
- 不改订单、收款/退款凭证、事件、复核、核验队列或下载权益；没有自动补账、结案、发送退款、关单或排队重试。
- 不做资金账、费率计费、银行到账、部分退款会计处理、服务里程碑核销或完整会计报表。
- 没有新依赖或迁移，现有0017账本必须完整。报告不是新财务凭证，不具备不可篡改存证或管理员签批效力。

## 数据流与保护

1. CLI读中央Settings的仓库根`.env`，进程变量优先。`WX_BILL_READ_ENABLED=false`时拒绝；日期、有效数据库主机/端口/库名、商户号必须手动确认。运维的OS/数据库权限是授权来源，**不是网站管理员登录态**。
2. 先只读核对迁移清单，结束数据库会话；再对固定 `/v3/bill/tradebill?bill_date=…&bill_type=ALL` 发签名GET。复用现有平台身份、新鲜度和原始应答验签；错误/无账单/生成中/限流不等于“零交易”。
3. 已验签元数据必须是`SHA1`＋40位哈希。下载链接仅接受主站HTTPS和两个官方示例路径：`/v3/billdownload/file`、`/v3/bill/downloadurl`，只允许一个有界token参数。不接受重定向、任意主机、端口、服务商子商户、压缩或上传者自报哈希。链接通常5分钟有效，过期后重新显式运行；不保存链接。
4. **账单文件下载应答按官方接口不带微信签名**，不能套用JSON应答验签器。用已认证元数据核对原始字节SHA1，再解析。SHA1是渠道协议的完整性字段，不冒称现代数字签名；另计算SHA256标识此次源文件。应用应答上限64KiB；文件4MiB/5000行、字段4096字符，申请＋下载总45秒。拒绝未知/旧版表头、坏前缀、截断、重复交易/退款号、金额/日期/商户不符及总笔数/汇总不符，不输出“部分成功”。
5. 按官方逗号＋反引号格式解析，不当成宽松Excel CSV；支持UTF-8 BOM与CRLF。不反解或输出商品、附加文本、付款用户标识。未转义控制字符（包括特殊SUB写法）拒绝，不声称覆盖所有历史商户格式。
6. 网络结束后再开有界数据库快照。PG用`REPEATABLE READ`＋`READ ONLY`、单语句10秒、快照20秒；SQLite显式BEGIN仅用于测试。付款日由`paid_at`而不是回调到达`received_at`选择。无时区账单时间明确按UTC+8解释；丹麦/操作机时区不参与计算，正式商户须验证跨日样例。
7. 既读当天原收款，也读账单指向的订单/交易号，即使本地日期较旧也检查身份冲突。未知付款时间单独报告，不静默排除；本地集合也限5000单。没有身份绑定的历史单、其他商户、manual/mock不自动纳入本商户对账。
8. 只在全部成功后生成`runtime/wechat-bills/日期-随机ID.json`。临时文件写完、fsync后用独占硬链接发布，已有报告不覆盖；失败清临时文件。总流程80秒协作预算不等于能强杀文件系统阻塞。中断后检查目录，只认可完整JSON，但仍须人工判断，不把“文件存在”当资金授权。

## 为什么金额和退款时间不能混用

- **订单金额**含用户支付和券额，是与本站原合同/PaymentReceipt比较的分金额。
- **应结订单金额**可能扣除了免充值券，不应拿它和原售价直接判差。例：原价10元、应结8元，本地1000分仍可匹配。
- 手续费等汇总只验证文件内部加总一致，不据此声称本地账或银行金额一致。所有金额用严格十进制定点转换，禁止float。
- `ALL`退款行的订单金额为0，申请退款金额才是此次申请额；“退款金额”又可能不含某些券。退款行时间是发起时间，状态在出账后不会更新。账单SUCCESS、PROCESSING、FAIL、CHANGE都只生成观察项，不能生成RefundReceipt。
- 同一付款可以同时有付款行和多个不同退款号的退款行。重复付款标识或重复退款标识整单文件拒绝；不同部分退款只作为观察。

## 运维执行

先读根目录[Windows新手逐步验收](../Windows新手逐步验收.md)本批章节，普通开发只跑合成测试。**下列是经另行批准的正式运维步骤，不是要求现在连接业务库或商户。**

1. 确认独立授权、目标数据库/商户、有效私有支付签名和平台验签配置；本CLI保守沿用现有微信APIv3配置检查，不提供绕过回调凭据的另一路配置。
2. 选择北京时间过去1—90天的明确日期；官方范围为近3个月，本实现取更保守的90天。次日10点后尝试较稳妥；NO_STATEMENT_EXIST/STATEMENT_CREATING不是空白成功报告。
3. 保证运行账户独占私有runtime目录；不能与`STORAGE_LOCAL_ROOT`、static、文档站、Web服务器映射目录重叠。不允许runtime或报告目录符号链接。不要把任意可写共享目录当私有目录。
4. Windows VS Code集成CMD＋现有Conda环境中，按实际目标替换占位内容，日期不要原样照抄：

```cmd
set WX_BILL_READ_ENABLED=true
python -m app.bill_reconcile --bill-date YYYY-MM-DD --confirm-target localhost:5432/codemax_db --confirm-merchant YOUR_MCHID
echo %ERRORLEVEL%
set WX_BILL_READ_ENABLED=false
```

`DATABASE_URL`优先于DB字段；确认的是其**实际生效**主机/端口/库，包括允许的host/port覆盖，不是默认DB_NAME。仅asyncpg PostgreSQL单目标，拒绝额外不明连接覆盖、多主机和SQLite业务运行。不得在命令、截图或报告中放完整带密码DSN。脚本不会替你设置/修改连接串或迁移数据库。

5. 退出码：**0**＝限定范围内未见差异，仍不是财务结案；**2**＝已生成报告，需要人工核查；**1**＝未得到可信对账结果，不能当零差异；**130**＝用户中断。参数用法错误由argparse退出2，但没有报告路径；不要仅凭2认定成功生成。
6. 文件名在终端输出，不打印订单正文、URL/token或数据库异常。用VS Code打开对应JSON，查看`counts`、`items`、`excluded_rows`和`snapshot`。只给有业务权限的人；不上传Git/聊天、不移动到storage/static、不要贴整份业务报告给诊断工具。
7. POSIX新文件0600、目录0700；Windows须单独配置并验收账户ACL。发布依赖本地文件系统硬链接，网络盘/FAT等不保证支持；失败非零而不是降级覆盖写。Linux测试不代表Windows NTFS/ACL已经验收。

## 如何处理报告

| code / 情况 | 含义和下一步 |
| --- | --- |
| `matched_payment` | 本次快照中订单、凭证、流水、商户/app、金额/CNY、已付状态和精确付款时间一致；不是永久结案 |
| `channel_payment_without_order` | 微信有单、本站找不到原订单；先核对环境/来源，不凭报告造订单或收入 |
| `channel_payment_without_receipt` | 找到订单但缺凭证；去[资金管理页](PAYMENTS_ADMIN_GUIDE.md)核对原合同，另行显式已验签查单 |
| `transaction_owned_elsewhere` | 交易号已有其他订单归属；保留现状，人工调查，不能挪流水 |
| `order_contract_mismatch` / `receipt_contract_mismatch` | 原渠道/商户/app/金额/币种/流水冲突；不得改旧凭证使差异消失 |
| `order_state_mismatch` / `paid_time_mismatch` | 订单状态/交易号/时间和凭证或账单不同；核对原单与时区，不手工改paid_at凑平 |
| `local_receipt_absent_from_bill` | 本地有付款，但该日账单未见；检查日期/商户/app、独立查询；**不撤销收入或下载权限** |
| `legacy_paid_without_receipt` / `local_paid_time_unknown` | 历史证据/时间不完整；保留历史，不捏造时间或补记财务成功 |
| `refund_observation_not_completion` | 退款发起快照；按原退款号另行核验。现有自动/人工核验仍仅支持原单全额政策，部分退款不能硬塞进去 |
| `excluded_rows > 0` | 其他app/非Native/非CNY未做本地匹配，仍计入文件完整性检查；报告需要核查，不冒称整个商户账平 |

报告包含渠道文件SHA256、本地快照摘要、读取时间、范围和必要订单/凭证字段；captured_at是应用采集结束时间，不是数据库提交序号或全局结算时点。不保留原账单、下载token、openid、商品、交付key或管理员依据。摘要用于定位和复查，**不是可独立重新验签的证据包**，也不是不可删除审计。备份/访问控制/保留期限由运维政策另定；没有自动清理或外部归档。重跑产生新报告，不能覆盖旧报告；迟到回调后结果可能正常变化。

## 验证与官方依据

`tests/test_wechat_bills.py`使用合成RSA签名、HTTP替身、私有临时文件和可丢弃数据库。完整PG初始化链路另外运行；PG并发快照用独立连接证明。没有真实下载、真实商户、Windows机器或生产数据操作。

- [申请交易账单](https://pay.weixin.qq.com/doc/v3/merchant/4013071227.md)：日期、ALL类型、SHA1元数据、下载地址和错误语义。
- [下载账单](https://pay.weixin.qq.com/doc/v3/merchant/4012791889.md)：文件应答不带微信签名，需校验哈希；五分钟地址和另一下载路径。
- [交易账单格式，2026-01-16版](https://pay.weixin.qq.com/doc/v3/merchant/4013071246.md)：27列/7项汇总、反引号、SUCCESS行两个退款ID为0、订单/应结/申请退款金额区别、退款发起快照不更新。

官方变更格式、压缩、多商户/服务商、大额大批量或网页操作需要重新评审，不通过放宽解析器/预算/签名校验来临时“跑通”。
