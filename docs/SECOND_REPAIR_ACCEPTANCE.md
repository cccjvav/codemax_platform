## 升级顺序（存量库）

1. 备份 PostgreSQL 与商品文件，确认可以恢复；停写、退出旧版本进程，不混跑旧认证代码与新 schema。
2. 在已有 0006 结构上，按顺序执行 `database init/migrate_0007_support_messages.sql`、`database init/migrate_0008_credential_revision.sql`。
3. 部署新后端、模板和全部 `app/static/js/` 分块。不要只拷贝入口 JS。
4. 旧的无 ver JWT 全部失效，客户/管理员重新登录；0008 还会清除未兑换授权码，重复执行同样会清码。
5. 已有 sys_user.role=1 的账号就是站内客服管理员。客户注册不能自行授予 role。生产环境必须更换/停用初始化的演示账号和演示凭据。
6. 保持单应用实例；设置真实代理直接对端的精确 CIDR。Docker CMD 已关闭 Uvicorn 二次代理头处理，由应用执行统一规则。

**不可用 full_init.sql 升级存量库：该文件会 DROP TABLE。** 本批没有自动执行任何用户生产库迁移。

- Chromium 动态渲染是明确停用，不是已通过真实浏览器验证。只有隔离出网渲染架构完成并验证后才能恢复。

- 未连接发票、自动退款或外部通知服务。管理员通过站内页面回复；不是后台通知系统。
- 当前商城仍是单个配置商品。更换商品不能直接复用旧订单指向的新文件 key；多 SKU/版本化商品目录需要单独建模。
