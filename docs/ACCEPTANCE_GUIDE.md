# 验收手册：本机浏览器、外部服务与上线条件

> 第一次在 Windows 操作？请从 [Windows 新手逐步验收](../Windows新手逐步验收.md) 开始：VS Code 集成 CMD＋Conda＋系统 Node，顺序命令、预期结果与失败恢复在一篇中完成。

当前默认提供方已改为 **Agnes 2.5 Flash**，向量增强默认关闭；基址、模型、旧 `.env` 迁移与分层诊断见 [Agnes 接入说明](AGNES_AI.md)。不要因配置聊天 key 就执行向量标定。

适用入口：[Windows + conda 指南](WINDOWS_CONDA.md)。本手册是**待执行步骤和通过标准**，不是已经执行完的报告。每项记录通过/失败/未执行/不适用及原因；未启用的功能不能为了“全绿”伪装成通过。

## 1. 是否只能在 Windows 上验收？

**不是。** 前次未能做真实浏览器验收，是沙箱下载浏览器失败，不是应用只能在 Windows 工作。

| 项目 | 可在哪里完成 | 所需条件与当前边界 |
| --- | --- | --- |
| Python/Node、SQLite、真实 PostgreSQL 自动化测试 | Windows、Linux、macOS 或 CI | 兼容解释器/Node/数据库；前次 CI 已验证其对应提交，但不代替你的本机环境验证 |
| 文档/页面真实浏览器、Drawio 交互 | 装有现代浏览器的电脑或浏览器测试环境 | 你的 Windows + Edge/Chrome 最方便；Drawio 还需可访问 diagrams.net |
| Word 附件实际显示 | 有 Word/兼容阅读器的设备 | 最好使用客户实际使用的 Windows Word；其他阅读器结果不能自动证明 Word 兼容 |
| 真实 LLM 和 embedding 阈值标定 | 可访问模型服务的电脑/服务器 | 你选择的模型、私密 key、测试语料和费用预算，不限操作系统 |
| 微信商户支付、回调、HTTPS/代理、重部署持久化 | 专用预发布部署环境 | 商户配置、公网可达 HTTPS 回调、实际入口代理；普通 localhost 不能替代 |
| 人工收款与站内客服 | 开发环境可验流程，真实核账需实际操作者与支付记录 | 人工确认有真实经济影响；没有核实到账不能确认 |
| OSS/COS、多实例共享限流、自动退款/开票/通知 | 当前不能靠本机点几下验收 | 尚未实现或未接入；先开发/配置，再制定对应验收，不是“缺 Windows” |
| Chromium 动态抓取 | 当前保持停用 | 安装 Playwright 不解除停用；需先实现隔离网络渲染设计，再做安全与功能验收 |

最低顺序：环境确认 → 自动化测试 → 本机浏览器/文件 → 实际启用的外部服务 → 预发布部署。未选择的商业通道注明不适用，并在页面/配置中保持关闭。

## 2. 准备与记录

- 人工操作使用独立本地开发库和测试商品；自动化测试使用另一专用测试库，不能互相混用。不要操作生产客户、真实文件或支付记录。
- 记录 `git rev-parse HEAD`、Python/Node/conda、Windows、浏览器和 Word 版本，以及测试日期。
- 准备两个客户账号A/B与管理员；客户从注册页创建，管理员由新库CLI bootstrap-admin创建、自己设置口令，不存在默认管理员。旧库按数据库指南停用公开种子后建立受控管理身份，不自动转移旧用户资产。
- 用**不同浏览器或不同浏览器配置文件**隔离 A/B/管理员；同一浏览器普通标签页通常共享 Cookie，不能把它们当作不同用户。
- 记录截图、失败步骤、请求路径/状态码、必要的响应 request id；不记录密码、Cookie、Authorization、支付密钥、完整下载签名 URL或客户隐私。HAR 文件通常含凭据，不直接上传。

可以将记录和脱敏截图放 `C:\work\codemax-evidence`（仓库外）。示例记录：

```text
提交 SHA：
环境 / 软件版本：
用例 ID：
执行步骤与预期：
实际结果：
状态：通过 / 失败 / 未执行 / 不适用
证据文件（已脱敏）：
失败或不适用原因：
复测结果：
```

## 3. DOC：离线文档与真实排版

在 conda 已激活的项目根目录：

```cmd
python scripts/check_docs_contract.py
python scripts/build_docs_site.py
start "" "docs\site\index.html"
```

再以 HTTP 方式检查（该窗口保持运行，Ctrl+C 关闭）：

```cmd
python -m http.server 8765 --bind 127.0.0.1 --directory docs/site
```

浏览器打开 `http://127.0.0.1:8765/`。这只是静态文档站，不需要运行应用或连接数据库。

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| DOC-01 | 从首页进入公共后端、路由、工具和本手册，再使用目录跳转 | 页面存在；目录落到对应标题，没有空白页或跳到示例围栏里的假标题 |
| DOC-02 | 分别在 file:// 与 HTTP 的子页搜索“conda”“验收” | 有对应标题/小节结果，链接指向正确页面；无需读取远端搜索服务 |
| DOC-03 | 符号索引搜索 create_access_token，展开签名与说明，打开源码链接 | 参数、返回注解（源码有才显示）、说明可读；源码定位到对应范围；缺 docstring 时明确提示，不显示编造说明 |
| DOC-04 | 切换“包含测试符号”和“只看公开”，查找测试函数 | 开关正确改变结果，取消公开限制才显示私有符号；计数同步 |
| DOC-05 | 桌面窗口约 1440px，缩小到 390/360px，再放大文字到 200% | 正文不被侧栏遮住；长签名换行；宽表格/代码区可横向滚动，控件可操作，无文字重叠 |
| DOC-06 | 只用 Tab、Shift+Tab、Enter 操作链接、筛选和展开区 | 焦点可见，不陷入不可退出的控件；内容仍能访问 |
| DOC-07 | 浏览器开发工具查看 Console 和 Network，再断开网络浏览已生成的文档 | 无影响阅读的 JS 错误；文档本站资源仍可用；外部链接打不开与离线站本身失效分开记录 |

源码页的长代码可横向滚动，这不等于整个页面可以任意溢出。某个设备出现样式问题就记为失败并提供脱敏截图，不能用“CSS 检查通过”覆盖实际结果。

## 4. APP：本地工具、身份与文档文件

按 conda 指南启动应用，打开 `http://127.0.0.1:8000/`；开发环境使用 mock 通道。

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| APP-01 | 匿名打开首页、ER、Mermaid、Drawio；再登录/退出 | 页面外壳可访问；私人云端操作要求登录；退出后清理用户显示，不把旧账号数据继续展示 |
| APP-02 | 在 ER 输入下方小型 DDL，生成 ER 图和 Word 附件 | 两张表和外键显示；文件确实下载；用 Word 打开无修复警告，中文、列名和关系含义符合输入 |
| AUTH-01 | A 在两个独立浏览器会话登录；其中一个通过 `/auth/password` 改密，再让另一个刷新私人页面/请求 `/auth/me` | 旧凭据被拒绝（接口 401）、要求重新登录；用新密码登录后私有数据仍在 |
| APP-03 | 按实际用户习惯缩放、滚动、刷新页面，并查看 Console | 没有阻断核心操作的脚本错误；控件不重叠；刷新不自动发起订单 |

```sql
CREATE TABLE customer (
    id INT PRIMARY KEY,
    name VARCHAR(40) NOT NULL
);
CREATE TABLE purchase (
    id INT PRIMARY KEY,
    customer_id INT REFERENCES customer(id)
);
```

模型 key 未配置时 Mermaid 返回明确不可用信息不算模型功能通过；实际模型内容另做第 7 节。自动化权限回归仍须运行，人工页面检查只是补充，不执行针对第三方的安全探测。

## 5. DRAW / MSG：编辑器与站内会话

### 5.1 Drawio（需要外部编辑器能正常加载）

1. 客户 A 登录，新建测试图，输入独特文字“验收 A-1”，保存。
2. 再改为“A-2”，**立即**保存或本地下载，不依赖等待 autosave；重新打开云文件/导出文件，确认是 A-2。
3. 在同账号两个独立页面打开同一版本，第一页修改保存，再在第二页尝试保存。期望冲突提示，第二页内容不被静默清空，不覆盖已保存的新版本。
4. 仅对测试图执行软删 → 回收站 → 恢复；确认活跃列表和回收站状态正确。
5. 再软删并永久删除，核对确认提示和不可恢复结果。不对有价值的图执行此步骤。
6. A 正在加载文件时退出，切换到 B；界面不应被 A 迟到的响应恢复。B 的列表不能显示 A 的文件。
7. 编辑器已经加载后，可在浏览器开发工具把当前页面网络设为离线，再保存；应提示失败而不是假成功。恢复在线后重试，图内容仍正确；测试完恢复网络模式。

记录编辑器是否加载成功、即时保存是否拿到最新 XML、冲突和账号切换结果。diagrams.net 无法访问时记“外部编辑器验收阻塞”，不能因为本地脚本测试通过就标记 E2E 通过。

### 5.2 站内客服

1. 客户 A 在 `/support/center` 留言；管理员在另一浏览器的同一路径刷新会话列表并回复。
2. A 在轮询后应看到管理员回复；刷新页面后历史仍在。用多条纯测试消息检查加载历史，不用真实客户内容造样本。
3. B 登录后只能看到自己的会话；管理员会话选择切换时不能把旧会话迟到的内容贴进新会话。
4. 断开当前页面网络后发送，必须提示未确认/可重试；恢复后重试，正常完成。
5. “服务器已收、客户端响应丢失”的精确去重场景由 `tests/test_second_frontend_regressions.py` 和 `tests/test_support_messages.py` 覆盖，普通离线按钮不等价于这个场景，不伪称人工完整模拟。

通过标准：双方可持续沟通、刷新保留、账号隔离、错误不假成功。该功能是站内轮询会话，不承诺邮件/手机通知或管理员实时在线。`/support/ask` 给出的人工入口不会自动创建持久会话。

## 6. PAY：模拟订单、下载重试和人工核账

### 6.1 无真实费用的本地演示

**只在独立开发库使用 mock。** 在应用目录创建一个新的测试 ZIP，不覆盖已有商品：

```cmd
python -c "from pathlib import Path; from zipfile import ZipFile; p=Path('storage/acceptance/demo.zip'); assert not p.exists(), 'Test file already exists; do not overwrite'; p.parent.mkdir(parents=True, exist_ok=True); z=ZipFile(p, 'w'); z.writestr('README.txt', 'CodeMax acceptance test file'); z.close()"
```

本地 `.env` 设置 `STORAGE_PRODUCT_KEY=acceptance/demo.zip`、`STORAGE_LOCAL_ROOT=storage`。要快速验证过期，可临时设置 `DOWNLOAD_URL_TTL=10`，重启应用；结束后恢复原值。不要更改真实商品 key 或业务库的运行配置来测试。

1. A 主动下单，确认商品名称/分金额显示合理；页面刷新或查看历史不应自动再下单。
2. 在模拟收银台确认该测试单，返回商城应显示已付款/可下载。
3. 领取链接，保存 ZIP 并打开其中 README.txt，内容完整。
4. 等超过设定 TTL 后尝试旧链接，应明确过期；回历史订单重新领取，新链接仍可下载。
5. 若要验传输中断恢复，使用自己生成的较大测试文件并在浏览器中取消下载，再从订单重领。小 ZIP 瞬间完成时不能声称测过中断恢复；记录未执行即可。
6. 切换 B 后看不到 A 的订单；A 已付款订单不能因为一次领链接或失败重试永久失去权益。

模拟流程通过不证明微信支付真实到账，也不证明 HTTPS/代理部署正确。

### 6.2 人工收款

manual 模式需要真实核账流程：展示的是个人收款码，平台不会自动知道是否到账。先在测试数据验证管理员操作与普通用户权限；真实确认只能在管理员核对独立支付记录、金额和订单后进行。

当前确认API `POST /shop/orders/{order_no}/confirm`必须带JSON：`{"reference":"TEST-BANK-0001","amount":19900,"evidence":"隔离测试核账依据"}`（真实使用必须换成实际唯一参考号和精确金额）。订单渠道必须manual，凭证与状态同事务；管理员ledger接口查看首次确认人及依据，不再只看日志。现有 `/admin/payments` 页面可执行受控人工核账、历史绑定与主动微信查单，步骤见[工作台手册](PAYMENTS_ADMIN_GUIDE.md)；不是完整会计/退款系统。开发 `/docs` 仍可用于测试接口，生产 API 文档关闭，不能为操作方便打开全站生产文档。正式使用前确定受控管理方式、日志保留和争议处理；未确定则不要开放该收款通道。

### 6.3 微信商户模式

在专用预发布环境完成商户配置、正确商品金额和可达 HTTPS 回调，用获授权的小额测试订单核对：下单、实际付款、平台回调、订单状态、文件下载和账单一致。涉及真实费用，先确认预算和人工善后方式；当前没有自动退款功能。

重复通知/签名等本地回归由现有测试验证；不要手工伪造或重放真实支付报文作为用户验收步骤。localhost 上看到二维码不能代替商户联调验收。

## 7. MODEL：实际模型与阈值标定

只有要启用模型能力时才需要真实 key。在**应用的本地开发目录**私密 `.env` 配置 LLM_API_KEY、LLM_BASE_URL、LLM_MODEL；LLM_EMBED_ENABLED=false、LLM_EMBED_MODEL 留空为当前默认；对话与向量模型不是同一个参数。请求可能付费，不提供生产客户资料作样本。

真实阈值测试的 skip 判定读取进程环境，仅在 `.env` 填 key 可能仍被跳过。以下命令先加载 `.env` 再让 pytest 收集，且只运行该一条实际模型用例：

```cmd
python -c "from dotenv import load_dotenv; load_dotenv(); import pytest; raise SystemExit(pytest.main(['tests/test_faq_semantic.py::test_calibrate_semantic_threshold', '-q', '-s', '-rs']))"
```

- 先用新终端，避免旧环境变量覆盖 `.env`。检查结果必须是实际执行，不能把 skipped 算通过。
- 检查同义问题命中正确 FAQ，无关问题低于阈值；打印建议值后，若当前值带外，会失败，这是有意提示。
- 有明确可分间隙时更新 `.env` 的 LLM_SEMANTIC_THRESHOLD，重启应用，并重新运行同一条测试。
- 分布重叠或命中错误 FAQ 时应调整语料/模型再标定，不靠随意降低阈值凑绿；此固定样本集通过也不代表所有真实用户问法都准确。
- 记录供应商、模型名/版本、日期、样本与建议阈值，不记录 key。再人工检查 Mermaid 输出可渲染、智能客服不编造未提供的业务承诺。

不要在配置真实 key/改过阈值的目录直接拿全量默认配置测试结果与 CI 比较；普通全量测试按 conda 指南在无 `.env` 的验收副本运行，避免意外费用和配置前提冲突。

## 8. DEPLOY：上线前仍需单独做的事

这部分不靠换成 Windows/conda 自动完成，按 [部署指南](DEPLOY.md) 在与正式拓扑一致的预发布环境执行：

- 核对实际域名、证书、代理直接对端和可信 CIDR；应用端口不允许绕过入口；浏览器生成的链接是正确 HTTPS 地址。
- 生产配置下 `/docs`、`/redoc`、`/openapi.json` 不开放；mock 通道关闭；演示身份/凭据已更换或停用。
- `/healthz` 可响应；`/readyz` 可查询测试数据库。数据库异常时就绪失败，不因此错误地批量重启健康进程。
- 备份测试数据，在预发布副本验证迁移与恢复；0008 会清未兑换授权码并使旧凭据需重登录。不得用 full_init 升级有数据的库。
- 在正常重启/重新部署后检查订单、消息和商品文件仍在。不要通过删除卷模拟重启。
- 当前单实例基线不等于已经支持多副本全局限流；当前只实现 LocalStorage，不把“有对象存储配置名”当成已有云适配器。
- Chromium 动态抓取继续停用。此项应记录“功能未开放”，不是让用户安装浏览器后取消安全边界。

## 9. 什么时候可以签收？

本地开发环境验收：解释器正确、依赖检查、自动化测试/构建/文档门禁成功，人工核心页面和文件操作满足上述标准；失败项已修复复测或明确阻塞。

商业上线验收：在本地验收基础上，实际选择的支付/模型/存储和预发布部署项也有证据。没有商户就可以选择不启用微信模式；未启用功能写“不适用/未开放”，不要对客户承诺它已可用。

报告最后列：提交 SHA、环境、每项状态、跳过原因、未解决项及是否影响所选业务上线。CI 绿灯、本机可启动、模型联调和商业上线是不同层次的结论。

## 第三批追加验收

下单前准备小于等于512MiB的本地真实文件。付款后覆盖原文件或改STORAGE_PRODUCT_KEY，重领链接仍须得到原字节。不要删`.snapshots`；模拟损坏只对独立测试快照操作，期望拒绝并保留权益，恢复相同字节再成功。旧库须迁移到当前0017（含0010合同、0011退款凭证及0012本地准备），历史未绑定订单不能自动取当前商品；管理员核实旧合同后绑定一次，过程见[第三批](../review/RELEASE_BLOCKERS_PHASE3.md)。

SQLite自动测试采用临时文件/独立连接，不再共享单连接来模拟并发。PG测试还运行实际SQL约束与触发器；独立数据库和storage的恢复、浏览器及真实商户仍需另验。

## 第四批：管理页与可信查单
