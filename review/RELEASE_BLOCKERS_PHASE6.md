# 第六批：成功退款凭证与订单下载权益

## 做了什么

本批是上一批异常复核之后的独立子项，不是完整退款系统。已有：单笔全额微信原路退款的只读查询核验、实际已完成人工全额退款的管理员登记、只追加退款凭证与原付款分离、原子审计、订单绑定短链和每次下载的退款门禁。退款申请、处理中、异常、未知与成功不能互相替代。

- 微信只GET普通商户退款查询，不发送退款POST。先记录带原退款单号的started，网络后重查管理员；验签和原商户/应用、原订单/交易号、退款号、CNY/ORIGINAL/全额/带时区成功时间全部验证。非成功仅记录观察，不撤销或恢复权益。
- RefundReceipt要求原支付凭证、一单一笔全额；来源/渠道退款ID唯一、来源/商户/商户退款号唯一。保留首次资金事实/人/时间，不改原收款和paid/downloaded。manual必须实际退款证据；不能把微信单借人工入口记退款。
- 0011与full_init同步，PG检查原付款归属/金额/时间并禁止修改/删除退款。仅在可丢弃库执行迁移验证，未操作业务库。
- v2域隔离JSON签名绑定订单/key/期限，旧key-only链接拒绝；未退款订单可重领。出口查询实时退款与冻结对象，耗时校验后再读退款；响应no-store。别的订单不撤权，迟到支付确认不恢复下载。
- 管理页分别显示原收款、成功退款与复核进度；客户订单显示refunded。复核摘要加入退款事实，退款started孤立60秒进入未知，非成功观察留待办。

## 依据与设计限制

已阅读微信官方普通商户[退款查询](https://pay.weixin.qq.com/doc/v3/merchant/4012791884.md)与[申请规则](https://pay.weixin.qq.com/doc/v3/merchant/4013071036.md)：受理成功不是实际退款完成，merchant refund number的重复原则不能被超时后换新号破坏。本批不实现申请接口/回调，不进行真实资金操作。

只支持一笔全额原路退款，不支持部分退款累计、异常转其他账户、mock退款、无原收款凭证历史单或服务里程碑取消。记录金额是合同退款额，不是现金到账、净结算额或手续费分录。没有客户自助申请/自动审批/自动补偿。人工证据真实性由实际管理员负责；自动化不能核验银行记录。

退款只限制新的下载授权，不能撤回已接纳的传输/已下载副本。短链仍能转交，DB/主机管理员仍可信，不是WORM。新应用要求0011；旧程序不认识退款，不得直接回滚运行旧下载代码。升级步骤与真人操作见[手册](../docs/PAYMENTS_ADMIN_GUIDE.md)及[Windows增补](../Windows新手逐步验收.md)。
