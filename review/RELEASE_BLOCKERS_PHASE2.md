# 剩余阻断项：第二批实施与验收

> 第二批历史快照；当前资金与交付进展见[第三批](RELEASE_BLOCKERS_PHASE3.md)。本页旧测试数和未结项描述对应f37bb8d，不覆盖后续实现。

## 范围与授权

用户在第一批 `f7e1cdc` 交付后要求继续处理剩余阻断项。本批先落实安全初始化/迁移基础、支付回调信任边界和生产SSO用途限制；新增迁移账本表及0009迁移，不新增依赖，不操作业务库，不调用真实商户，不更换Agnes/启用embedding。

## 已实现的合同

### 1. 初始化不再带公开账号，也不允许重建已有数据

- `full_init.sql` 移除全部DROP和身份种子，并在public已有表/视图/序列时拒绝。CLI没有默认动作，不带子命令只显示帮助并非零退出。
- 使用已存在的专用空库，显式 `--confirm-database` 同时核对配置与实际连接库名；不再自动创建数据库、不在导入时打印连接信息。
- `bootstrap-admin` 交互输入新口令（至少12字符、最多72 UTF-8字节），只创建第一个启用管理员，拒绝覆盖/提权现有账号。没有默认口令。
- 演示身份移到 `seed_demo.sql`，仅显式development命令、空身份表及SQL opt-in同时满足时才能创建；生产拒绝使用。旧记录和原始公开凭据仍在Git历史，这是历史证据而非新秘密。

### 2. 迁移有签收本、互斥锁和失败回滚

`schema_migration`保存四位版本、SQL SHA-256及时间。`init`建表与基线签收同事务；`migrate`验证连续版本/校验和，SQL与账本同事务提交，拒绝修改已应用SQL或悄悄降级。PG事务级advisory lock在连接间互斥；锁等待10秒、单SQL120秒，事务结束释放。

没有账本的旧0008库必须显式 `adopt-legacy-0008`。该操作核对表列与关键索引后建立基线并执行0009：停用原始公开种子凭据、递增对应用户凭据版本、清停用身份的授权码，**不删除原订单、消息或图表**。再次migrate不重复清码/递增版本。原账户资产不自动转给新管理员。

这是针对已核准0008的接入方案，**不是早于0008的全自动升级或完整DDL等价证明**。旧迁移的时区、重复pending和清码副作用仍要人工核准。原SQL历史不编辑，`.gitattributes`强制SQL使用LF，保证跨平台校验和稳定。

### 3. 生产启动拒绝不完整账本和演示凭据

lifespan在接收流量之前只读检查：迁移账本完整且校验和一致、已知弱管理员口令/启用的演示SSO凭据不存在、至少一个启用管理员。检查有10秒总时限；失败不自动迁移、不打印数据库URI。即使启动失败也清理CPU池和数据库engine。

Settings现在固定读取仓库根.env，CLI与应用共用DATABASE_URL优先级；不再依赖启动目录。Docker上下文必须携带SQL历史供校验，Compose取消自动SQL挂载并固定连接示例db容器，初始化/升级/管理员创建由显式维护命令完成。操作步骤已同步[数据库指南](../database%20init/README.md)、[Docker部署说明](../docs/DEPLOY.md)和[Windows逐步验收](../Windows新手逐步验收.md)。

### 4. 支付不能只验证签名公式

- 回调平台serial必须与本地可信X509证书匹配，证书必须在有效期，RSA至少2048位；裸公钥模式额外要求精确WX_PLATFORM_KEY_ID。不能把商户WX_SERIAL_NO当平台ID，也不从回调提供的网址获取密钥。
- 成功通知须匹配本商户mchid、appid、NATIVE、CNY及AEAD_AES_256_GCM资源类型，再验证订单/金额。原有真实RSA/AES合成测试保留，测试头改成真实自签证书的serial而不是占位字符串。
- 下单响应流式限制64KiB、总等待20秒，并校验JSON/二维码字符串及weixin协议；网络、畸形结构与解密后的非法UTF-8受控失败，服务商原始正文不透传。
- 第一批的预支付前本地commit和失败同号重试合同保持不变。
- 创建预支付前先验证本地回调凭据：APIv3密钥32字节、平台证书/公钥可解析、RSA强度和证书时段合格。不合格503，既不建订单也不请求商户；不等于验证控制台登记值或回调可达性。

仍未实现完整财务事件/尝试账本、预支付响应验签、平台密钥自动轮换、跨订单唯一流水、查单/关单/退款/争议、商品交付对象快照及人工核账持久证据。非成功事件的现有确认语义不等于已处理退款；**真实资金发布仍阻断**。

### 5. SSO先限定用途，不假装已经支持第三方最小权限

production默认 `OAUTH_TRUSTED_CLIENT_IDS=[]`，授权和兑换两个入口都拒绝未显式信任的客户端；生产回跳只允许HTTPS。配置是JSON数组，示例只有在确认是自己控制的站点后才能填入["tools"]。客户端/授权码的NUL和长度边界受控失败。

现有SSO发的是完整站点JWT，能以该用户身份访问站点接口；不是scope/audience隔离令牌。可信第一方约束减少误开放，但**不关闭第三方OAuth/PKCE/一次性同意/会话治理阻断**。
